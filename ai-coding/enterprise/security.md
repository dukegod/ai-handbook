# 安全与合规

> **TL;DR**：AI 编程的安全核心是"数据不泄露、代码不注入、操作可审计"。

⏱ 预计阅读时间：6 分钟

## 你能在这里学到

- AI 编程的安全风险
- 数据安全措施
- 代码安全措施
- 合规要求

## 安全风险

### 1. 数据泄露

AI 工具可能将代码/数据发送到外部服务器。

**风险**：

- 源代码泄露
- 密钥泄露
- 商业秘密泄露

### 2. 代码注入

AI 生成的代码可能包含安全漏洞。

**风险**：

- SQL 注入
- XSS 攻击
- 命令注入

### 3. 依赖风险

AI 可能推荐有漏洞的依赖。

**风险**：

- 已知漏洞
- 恶意包
- 许可证问题

## 数据安全措施

### 1. 数据分类

| 类型 | 风险 | 措施 |
|------|------|------|
| 公共代码 | 低 | 可上传 |
| 内部代码 | 中 | 私有化 |
| 敏感代码 | 高 | 禁止上传 |
| 密钥 | 极高 | 禁止上传 |

### 2. 数据脱敏

上传前脱敏敏感信息：

- API Key → `sk-ant-****`
- 密码 → `****`
- 内部 URL → `https://example.com`

### 3. 传输加密

确保 AI 工具使用 HTTPS 传输。

## 代码安全措施

### 1. AI 代码审查

用 AI 审查 AI 生成的代码：

```bash
claude -p "审查这段代码的安全问题，包括 SQL 注入、XSS、命令注入等"
```

### 2. 静态分析

用静态分析工具检查代码：

```bash
npm audit  # 检查依赖漏洞
eslint .   # 检查代码规范
```

### 3. 动态分析

用动态分析工具检查运行时安全：

```bash
npm run test:security  # 安全测试
```

## 合规要求

### 国内合规

| 法规 | 要求 | 措施 |
|------|------|------|
| **数据安全法** | 数据分类分级 | 建立数据分类体系 |
| **个人信息保护法** | 个人信息处理 | 脱敏、加密、授权 |
| **网络安全法** | 网络安全保障 | 安全审计、漏洞修复 |

### 国际合规

| 标准 | 要求 | 措施 |
|------|------|------|
| **GDPR** | 欧盟数据保护 | 数据最小化、用户授权 |
| **SOC 2** | 安全控制 | 安全审计、访问控制 |
| **ISO 27001** | 信息安全管理 | 安全管理体系 |

## 安全最佳实践

### 1. 最小权限

只给 AI 工具必要的权限：

```json
{
  "permissions": {
    "allow": ["Read(src/**)", "Grep(src/**)"],
    "deny": ["Bash(rm *)", "Write(.env)"]
  }
}
```

### 2. 审计日志

记录 AI 工具的所有操作：

- 读取了哪些文件
- 修改了哪些文件
- 执行了哪些命令

### 3. 定期审查

定期审查 AI 工具的使用情况：

- 是否有异常访问
- 是否有数据泄露
- 是否有安全漏洞

## 常见坑

**1. 不要忽略密钥管理**

密钥不能上传到 AI 工具。使用环境变量或密钥管理服务。

**2. 不要忽略依赖安全**

AI 推荐的依赖可能有漏洞。定期检查依赖安全。

**3. 不要忽略审计**

记录 AI 工具的所有操作，便于事后审查。
