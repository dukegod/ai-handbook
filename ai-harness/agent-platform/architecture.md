# AI 研发 Agent 平台：能力架构

> **TL;DR**：平台以统一对象连接工作，以授权和证据约束推进。

> **理论草案**：以下是可替换的职责划分，不预设实现方式或运行能力。

## 六组能力及其责任

| 能力 | 承担的责任 | 关键边界 |
| --- | --- | --- |
| 工作空间与人机交互 | 关联项目、事项、参与者、产物和待审决定 | 视图相同不代表访问权限相同 |
| 任务与状态协作 | 表达依赖、归属、阻塞、交接和恢复条件 | 任务完成不等于整项交付完成 |
| Agent 与 Skill 管理 | 组织角色、方法、适用范围和能力版本 | 能力被登记不等于经过有效验证 |
| 上下文与知识 | 装配当前目标、契约、历史证据和适用规则 | 历史经验不能覆盖当前有效约定 |
| 工具与执行边界 | 连接实际操作及其授权、环境和资源限制 | 工具可用不等于获得操作权限 |
| 产物、证据与观测 | 关联结果、版本、来源、成本和运行情况 | 接口回执不必然证明预期效果发生 |

授权、版本和责任应贯穿六组能力。工作空间呈现对象，任务组织工作，Agent 使用相关上下文与 Skill 调用工具，产物和证据再支持状态判断及人的决定。

## 一次任务的概念链路

以修正搜索权限为例：先关联需求和当前规则，再明确任务边界与输入；执行者取得所需上下文，在授权范围内修改；验证结果关联具体产物、环境和验收；随后判断是继续、返工、待审还是阻塞。

这是一条责任链，不规定所有操作都串行。执行结果与平台展示不一致时，应先查证实际状态，不能靠更新界面消除矛盾。

## 三种权威来源

**约定来源**说明应该发生什么，包括目标、验收和授权；**结果来源**说明实际发生什么，包括变更、执行记录和观察；**状态来源**表达当前可以作出的判断，并引用前两者。

同一对象应有明确的权威来源。多个界面可以展示同一结果，但不应分别改写结论；变更影响既有证据时，需要保留原记录并复核适用性。

## 异常与治理

缺少环境应表现为阻塞或未执行；外部操作结果未知时应先核对，不能直接认定失败后重做。输入变化、权限撤销和并发冲突均可能改变可执行范围，需要重新判断。

可审计意味着能够追溯决定与操作，不等于决定正确。平台只能强制检查已表达且可观测的规则，无法由此证明需求完整、判断可靠或价值实现。

## 与自交付架构的对应

自交付的四层描述目标决策、交付组织、专业能力、执行证据。这里六组能力是平台对这些责任的承载方式，一组能力可以服务多层；它们也不是九阶段的替代流程。
