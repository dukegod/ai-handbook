# 提示词入门

> **一句话**：提示词（Prompt）就是你跟 AI 说的话。好提示词的秘密不是"魔法咒语"，而是**把上下文给足、把要求说清**。

## 一、万能公式

```
角色 + 任务 + 上下文 + 格式 + 边界
```

举例：

> **角色**：你是资深前端工程师。
> **任务**：帮我审查这段 React 代码的性能问题。
> **上下文**：这是我们的商品列表页，数据量约 1 万条，用虚拟滚动实现。
> **格式**：按"问题 / 严重程度 / 修复建议"三段输出。
> **边界**：只关注首屏性能，不考虑 SEO。

对比一个"白板"prompt：`帮我看看这段代码` —— 模型只能猜你的需求。

## 二、五步心法

**1. 给上下文，别让 AI 猜** —— 文件内容、报错信息、业务背景，能贴就贴。模型只知道你给它的。

**2. 把任务拆小** —— "帮我写一份季度报告"太抽象。拆成：先列大纲 → 再写引言 → 再逐段展开。一次一个任务，质量指数级提升。

**3. 指定输出格式** —— 表格 / 列表 / Markdown / JSON / 代码，说清楚。要 500 字就写"500 字"，要 5 条就写"5 条"。

**4. 给示例（Few-shot）** —— 给一个"输入 → 期望输出"的样例，比十句描述都管用。

**5. 迭代而不是重写** —— 第一次结果不好是常态。继续对话："第 2 点再展开" / "语气改正式一点" / "用第一人称"。对话本身是上下文，越聊越懂你。

## 三、进阶技巧（按需取用）

| 技巧 | 用法 | 适用 |
| --- | --- | --- |
| 思维链 | "请一步步推理，最后给结论" | 数学 / 逻辑 / 复杂分析 |
| 角色扮演 | "你是十年经验的 X 专家" | 领域问答 / 审查 |
| 反向提问 | "先问我 3 个澄清问题再回答" | 需求不明确时 |
| 约束排除 | "不要用术语 / 不要超过 200 字" | 控制输出 |
| 多轮打磨 | 让它生成 3 个版本再选 | 文案 / 设计 |

## 四、常见错误

- ❌ **一次问太多** —— 模型只会认真对待前几个
- ❌ **不提供上下文** —— "帮我优化"（优化什么？给谁看？）
- ❌ **用模糊形容词** —— "更好""更专业"→ 改"更短""更口语化"
- ❌ **不验证结果** —— AI 输出 ≠ 正确输出，重要内容必须核验

## 关键洞察

- **提示词是"沟通"不是"咒语"**——像给新同事交代任务一样写提示词
- **上下文 > 措辞**——给足背景比雕琢措辞重要 10 倍
- **迭代是常态**——别期待一次成功，把对话当协作
