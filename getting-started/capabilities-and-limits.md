# 能力与边界

> **一句话**：AI 在"生成内容"和"知识工作"上已接近人，但在"事实准确性"和"自主执行"上仍不可靠。**知道它不行什么，比知道它能什么更重要。**

## 一、能做（截至 2026-08）

| 领域 | 能力水平 | 典型任务 |
| --- | --- | --- |
| 文本生成 | 🟢 优秀 | 写作、改写、翻译、总结、头脑风暴 |
| 代码 | 🟢 优秀 | 生成、补全、解释、重构、写测试、代码审查 |
| 知识问答 | 🟡 良好 | 常识与领域知识；**需验证引用** |
| 推理 | 🟡 良好（推理模型更强） | 数学、逻辑、规划、分析 |
| 图像理解 | 🟢 优秀 | 识别、OCR、图表解读、截图描述 |
| 长文档 | 🟡 良好 | 摘要、对比、结构化提取（受上下文窗口限制） |
| 语音 | 🟡 良好 | 实时对话、转写、翻译 |

## 二、不能做（红线清单）

**⛔ 事实不可靠** —— 幻觉是结构性缺陷，不是 bug。涉及引用、数字、法规、新闻，**必须人工核实**。

**⛔ 无自主判断** —— 它不会说"你这里需求有矛盾"——它只会照做。需求质量决定结果质量。

**⛔ 隐私与合规** —— 你发的内容会被服务商处理。机密信息、用户数据、代码仓库**不要直接粘贴**给公共 API。

**⛔ 时差敏感** —— 训练截止日期之前的知识是盲区。最新动态需要联网或人工补。

**⛔ 版权边界** —— 生成内容可能包含训练数据中的受版权材料；商业用途需自查。

## 三、翻车场景 Top 5（来自真实使用）

1. **拿它当搜索引擎** —— 它给你一个"看起来很像真的"答案，实际是编的 → 用带联网的产品，或人工验证
2. **一次问太多** —— 一个 prompt 塞 10 个问题 → 它只认真回答前 2 个 → 拆开问
3. **期待它"理解你的项目"** —— 它只知道你贴给它的东西 → 把上下文给够（文件、报错、约束）
4. **让它做"你都没想清楚的事"** —— "帮我优化这个系统" → 它是回音壁，先自己定目标
5. **把产品功能当模型能力** —— "它明明记得我上次说的！" → 那是产品层记忆，换个窗口就没了

## 四、如何安全地用

| 场景 | 可用策略 |
| --- | --- |
| 重要结论 | 让它给出"引用来源"或"推理过程"，再人工核验 |
| 代码 | 一定跑测试；AI 生成的代码 70% 能跑，但边界 case 常错 |
| 机密数据 | 用企业合规产品（Azure / Bedrock / 私有化部署）或脱敏 |
| 关键决策 | 只当参谋，不当决策者 |

## 关键洞察

- **AI 是"提效杠杆"不是"替代品"**——它放大你的能力，前提是你自己有判断力
- **幻觉无法消除，只能管理**——验证流程比提示技巧更重要
- **越专业的任务，越需要人把关**——法律、医疗、财务领域尤其如此
