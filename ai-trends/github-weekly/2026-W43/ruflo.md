# ruvnet/ruflo：Agent Federation —— 给 Agent 一个跨信任边界的 Slack

> **TL;DR**：ruflo 提出的 Agent Federation 在形态上非常像「给 Agent 用的 Slack」——跨机器、组织、云区的 Agent 可以互相发现、证明身份、协作完成任务。**但它比 Slack 多了一个 Slack 没有的维度：信任等级是动态升降的。**

📅 数据窗口：2026-10-15 ~ 2026-10-21 ｜ 🏷️ 多 Agent 协作 / 信任边界 ｜ 最新 release：`v3.59.6`（2026-10-21）

## 是什么

[ruflo](https://github.com/ruvnet/ruflo)（Claude Flow）自称是「the original agent harness」，提供 100+ 专用 agent、swarm 编排、持久记忆、学习循环、模型路由等插件能力。

其中 **Agent Federation** 是最有想法的部分。它的类比是：Slack 给了团队频道，Federation 给 Agent 同样的东西——**跨信任边界的共享工作空间**。不同机器、组织、云区上的 Agent 可以互相发现、证明身份、协作完成任务。

关键的机制细节：

- **身份**：Agent 加入 federation 后，用 **mTLS + ed25519** 验证，协议层处理握手与证书管理，用户只需 `federation init` / `federation join`。
- **数据边界**：**PII 在离开节点前就被剥离**，每条消息可审计。
- **分级信任**：不是所有频道都同等可信。**不可信的 Agent 可以以更低权限参与——它们能看到发现信息，但看不到你的记忆**。随着可靠性被证明，信任自动升级；一旦表现异常，**立即降级，无需人工介入**。

## 技术亮点

**「信任等级随行为动态升降」是这里最值得抄的设计。** 大多数多 Agent 系统只有两种状态：完全信任（则必须共享全部上下文）或完全不信任（则无法协作）。ruflo 用「可见性分级 + 行为驱动的信任升降」给出了中间态——**低信任 Agent 也能参与协作，只是拿不到敏感资产**。

这个设计对企业的现实意义是：跨部门、跨供应商、跨云区的 Agent 协作，最大的障碍不是协议不通，而是**没人敢把数据交给一个不完全知根知底的 Agent**。把信任做成**连续变量**而不是**布尔值**，等于把协作的准入门槛从「审批一次」变成「边跑边评估」。

另外两个细节值得注意：**PII 出节点前剥离**（不是事后审计，是传输前拦截），以及**降级无需人工介入**——这意味着信任模型是运行时策略，而不是配置项。

## 后续发展建议

**这套东西和 NVIDIA OpenShell 是同一个问题的两个面**：ruflo 解决「Agent 之间怎么安全协作」，OpenShell 解决「Agent 怎么被安全地限制在自己的权限内」。两者合起来才是一个完整的企业 Agent 信任模型。

三个具体判断：

- **Federation 的真正瓶颈不是协议，是信任证明的来源。** mTLS + ed25519 证明的是「你是你」，不是「你值得信」。**信任等级要能被动态升降，就必须有外部可验证的行为证据**——比如 Agent 在过往任务中的可复现性、其产出被采纳的比例、由谁来背书。当前这些证据得从 Agent 生态之外获取（CI 记录、审计日志、人工验收记录）。这会是「Agent 信任」这个赛道真正的难点，也是最值得投入的地方。
- **PII 剥离应当是默认的「降级呈现」而非「脱敏」。** 剥离 PII 只能处理已知模式的数据形态。更彻底的做法是**按策略决定 Agent 能看到哪一类信息**，而不是先给全量再删敏感字段——顺序反了，因为删不干净的概率远高于一开始就少给。后者正是 OpenShell 的做法（凭据只在发往白名单端点时才注入）。
- **对企业内部平台的直接启示**：如果 OD / ODE / OxygenSE 之间要跨系统跑 Agent，需要的正是这套东西——**跨信任边界的身份验证 + 分级可见性 + 行为驱动的信任升降**。建议把「Agent 信任等级」作为一个一等建模概念，而不是在集成时临时加的开关。跨系统边界设计可参考 [A2A 协议行业深度调研](../../industry/a2a-protocol.md) 的能力差距分析。

**风险提示**：Federation 是本周榜单里技术野心最大、也最难验证的项目。它的机制描述清晰，但**跨组织联邦的真实运行成本（延迟、证书轮换、策略同步）几乎没有可见数据**。建议当作「架构参考」读，不要当作可直接采用的实现。
