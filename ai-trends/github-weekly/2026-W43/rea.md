# morluto/rea：把逆向工程变成 Agent 可复现的流水线

> **TL;DR**：REA 用一个 MCP 服务把「桌面应用行为 → 原生二进制」的分析链路接起来，Agent 通过 MCP 提问、REA 返回带证据的结论。本周涨星 +157,631，是第二名的 9 倍——但这个数字本身比它的方法论更值得警惕。

📅 数据窗口：2026-10-15 ~ 2026-10-21 ｜ 🏷️ Agent 能力边界 / 逆向工程 ｜ 最新 release：`rea-agents-6.7.0`（2026-10-18）

## 是什么

[REA](https://github.com/morluto/rea)（Reverse Engineer Anything）定位是**一个 MCP 服务**：你的 Agent 调用它来检查目标、追踪相关代码，REA 返回**带证据的发现**（代码引用、符号、调用关系、以及明确的「未知项」），Agent 再基于这些证据追问、解释行为，或者直接写出并测试实现。CLI 走的是同一套工作流。

它支持的目标类型覆盖面很宽：

| 目标 | 返回什么 | 依赖 |
| --- | --- | --- |
| 桌面应用安装目录 | 运行时候选、支撑文件、组件标记 | 内置目录 / header 检查 |
| 原生二进制 | 伪代码、汇编、字符串、符号、调用与引用 | Hopper / Ghidra / IDA |
| Go 二进制 | 内嵌编译器版本、模块、replacement、构建配置 | 内置静态解析 |
| ELF 布局 | 段、节、原始符号 / relocation、缓解措施候选 | 调用方提供 pwntools |

## 技术亮点

1. **证据优先的返回契约。** 它不是把一堆日志丢给模型，而是明确区分「已确认的发现」和「未知项」。这与 Agent 工程里反复出现的教训一致：模型在信息缺失时倾向于编造，所以契约层面就必须给「不知道」留位置。
2. **MCP 作为统一接口。** 同一个 REA，Claude Code / Codex 通过 MCP 调用，终端用户走 CLI。工具接入层与能力层解耦，这正是它一周内被大量 harness 用户接受的原因。
3. **依赖外部逆向器而非重造轮子。** Ghidra / Hopper / IDA 都在支持列表里——定位是编排层，不是替代品。README 里的 showcase 也集中在真实场景（复现音效声像计算、追踪 Electron 剪贴板桥接），说明它解决的是「不知道从哪下手」而非「工具不够强」。

## 后续发展建议

**这个项目真正的价值不在仓库本身，而在它揭示的一件事：Agent 的能力上界正在从「调用 API」转向「操作无结构的真实资产」。** 逆向工程长期是 Agent 的硬骨头——二进制没有 API，没有文档，没有结构化 schema。本周它单周涨 15.7 万 star，说明社区对「Agent 能读懂别人写的东西」这件事的需求远大于供给。

我的判断是接下来会出现的三个方向：

- **资产语料层。** REA 目前每次分析都是一次性的。真正的护城河是**沉淀过的分析产物**：把某个软件的符号表、调用图、行为特征沉淀成可复用资产，后续 Agent 直接查而不重跑分析。谁先把「可检索的逆向知识库」做出来，谁就吃下这波流量。
- **从单目标到目标图谱。** 现在是一次问一个目标。下一个台阶是让 Agent 自己决定「先分析哪个、哪些之间有依赖」，把逆向变成自主规划任务。这依赖 MCP 之外的能力：任务分解、预算控制、以及失败时的降级路径。
- **合规边界会成为一等公民。** 逆向工具天然带双重用途（dual-use）。README 里的 Disclaimer 只是个免责声明段，真正的工程解法是**把授权范围写进策略**——这恰好和本周 NVIDIA OpenShell 做的内核级策略拦截是同一个方向。参考 [NVIDIA OpenShell 深读](./openshell.md)。

**风险提示**：涨星 45% 的存量占比说明这个项目是**现象级爆发，不是渐进积累**。爆发期项目普遍面临的问题是维护跟不上、社区治理滞后。建议观察它的 issue 响应速度与 release 节奏（本周已有 6.7.0 版本，节奏不错）再决定深度投入。
