## 是什么

[ZhuLinsen/daily_stock_analysis](https://github.com/ZhuLinsen/daily_stock_analysis) 是基于大模型的多市场自选股分析系统，覆盖 **A 股 / 港股 / 美股 / 日股 / 韩股 / 台股 + ETF**，每日自动分析并把「决策仪表盘」推到 **企业微信 / 飞书 / Telegram / Discord / Slack / 邮箱**。

核心能力：

- **AI 决策报告**——核心结论、评分、趋势、买卖点位、风险警报等。
- **多市场数据聚合**——行情、K 线、技术指标、新闻、公告、基本面，**并标注各市场的数据源与能力边界**。
- **Web / 桌面工作台**——手动分析、任务进度、历史报告、回测、持仓、配置管理。
- **Agent 策略问股**——**多轮追问**，内置 15 种策略（均线、缠论、波浪等），通过 Web / Bot / API 提供。
- **智能导入与补全**——图片、CSV / Excel、剪贴板导入；代码 / 名称 / 拼音 / 别名补全。

部署路径：**Fork 仓库 → 在 Secrets 里配模型和通知渠道 → GitHub Actions 每天自动跑**，README 称 **5 分钟完成部署、零成本、无需服务器**。也支持 Docker、定时任务和 FastAPI。

## 技术亮点

**第一，零服务器部署靠的是「Secrets 填参数 + Actions 跑定时任务」，比自建服务更适合小团队。** README 必填项：`STOCK_LIST`（必填）、一个模型 key（推荐 Modelflare / x6.ai）、一个通知渠道 webhook。**没有数据库、没有后端进程、没有账号体系——状态就是 Actions 的运行记录 + 用户的 Secrets。**

**第二，它把「数据源」做成了可替换层，并标注稳定性差异。** 模型侧：Modelflare、x6.ai、AIHubMix、Gemini、OpenAI 兼容（DeepSeek 等）、Claude、Ollama 本地。行情侧：TickPlus（推荐）、AkShare、Tushare、Pytdx、Baostock、YFinance、Longbridge。新闻侧：SerpAPI、Anspire、Tavily、Bocha、Brave、**MiniMax**、SearXNG。社交舆情侧：Stock Sentiment API（**仅美股**）。README：**免费源受上游限流、接口变动和网络波动影响，稳定性不保证；批量分析建议配 token 型数据源**。**每条数据源都有降级路径**，这是它能跑在免费配置上的前提。

**第三，它是本周唯一把「模型路由」做成用户可见配置的项目。** README 说需要多模型、图片识别、本地模型或**高级路由**时再看 LLM 配置指南——**「多模型 + 路由」不是隐藏实现，而是显式的配置面**。**模型从「一个」变成「一组」，路由就必须变成配置而不是代码。**

**第四，「多轮追问的策略问股」把 Agent 用在了「回答问题」而不是「生成报告」上。** 15 种内置策略是**可被追问的显式知识**，不是黑箱提示词——**Agent 的价值越来越体现在「可被交互探查的中间产物」上**。

**第五，5.7 万 fork 是关于「分发形态」的信号。** Star 数反映关注，**fork 数反映「我要自己跑一份」**。79% 的 fork/star 比意味着真实使用模式是：**Fork → 改 `STOCK_LIST` 和 Secrets → 用自己的 Actions 跑**。README 里专门给了国内部署路径、Secrets 表格、各市场 Actions 映射。**这与 skill 类项目靠包管理器分发完全不同。**

## 后续发展建议

**最重要的判断是：这是本周唯一一个「非 Agent 原生、但把 Agent 塞进成熟自动化流水线」的项目——它证明 Agent 能力可以嫁接，不必重写整条链。** 四个判断：

- **「Fork + Secrets + Actions」是一种值得内部平台借鉴的极简交付形态。** 它的优势是**零运维、零账号、零数据库**——**配置即代码，配置即状态**。内部平台若有「让非开发角色用上 Agent 能力」的需求，**这条路比「部署一套服务再发账号」轻得多**。代价是**配置在 Secrets 里不可审计、不可版本化**——**内部用时应换成「配置文件 + 密管分离」，不要直接照抄 Secrets 承载业务配置**。

- **「每个数据源都有降级路径」是这类系统长期跑下去的关键工程细节。** 免费行情源限流、接口变更、字段改名——**任何一个都会让整条日报静默失败**。**建议把「数据源降级链」当成一等设计对象**，且**降级时要明确标记而不是静默替换**。

- **「把策略显式化、再让 Agent 追问」是垂直领域 Agent 的可复制范式。** 15 种策略是可命名、可组合的条目，**用户问的是「按这个策略看会怎样」，而不是「让 AI 帮我分析」**——**建议把领域知识拆成这种「可命名的策略条目」，可被引用、可被追问、可被审计**。

- **但这个项目也暴露了垂直 Agent 的通用风险：输出看起来完整，实质可靠性没有保障。** 报告字段包含「评分、买卖点位」这类高风险结论，输入却是**免费、稳定性不保证的数据源 + 通用大模型**。**建议把「结论」和「证据」分离展示**——**证据必须可点开回溯**。

**风险与局限**：**5.7 万 fork 也意味着上游改动会被 5.7 万份副本分摊掉**——**上游改了配置格式或数据源契约，所有 fork 都要各自修**；**README 里的「零成本」是就服务器而言，不是就 API 费用而言**；**它面向有投资决策需求的人，责任边界在项目之外**。
